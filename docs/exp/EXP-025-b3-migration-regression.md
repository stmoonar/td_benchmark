# EXP-025: b3 迁移退化排查

> ⚠ 根因修正：真实原因是 StaticSharedExpert 实现退化（每调用全流程 fused_experts + FP8 输入被反量化），非 separate-dequant 未迁移——overlap 模块两边逐字节一致。见 EXP-026。

> Date: 2026-07-05 / GPUs 9,11,13,15

## TL;DR
b3 默认 (2,4) 配置比老实现慢 0.6ms（5.84 vs 5.26）。大部分差距来自 chunk 配置而非代码缺陷：
改为 (1,4) 后 b3=5.62ms，仅比老慢 7%（0.36ms）。剩余差距疑为老仓库 FP8-RS 的 separate-dequant
优化路径在迁移时未完全保留（老仓库 FP8_RS_OVERLAP_OPT.md 有该路径的性能记录）。

## 排查结果
| 配置 (gateup, down) | 新 b3 (ms) | 相对 a1 | 备注 |
|---|---|---|---|
| (2, 4) 默认 | 5.837 | 0.96x | |
| (4, 4) | 6.201 | 0.91x | 更差 |
| (1, 4) | 5.618 | **1.00x** | 接近 a1，最优 |
| (1, 1) | 5.682 | 0.99x | |

老实现: 5.259ms (1.05x vs a1=5.537)

## 结论
- chunk 配置 (1,4) 可恢复 b3 到与 a1 持平，但仍未达到老实现的 1.05x 水平
- 剩余 0.36ms 差距归因于 FP8-RS separate-dequant 路径未完整迁移，不阻塞报告
- **b3 报告口径：双口径**（老实现 1.05x vs a1 / 新实现 0.96-1.00x vs a1，差异为迁移退化非物理规律）
